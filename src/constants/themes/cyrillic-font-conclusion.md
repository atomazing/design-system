# Заключение по кириллической типографике для тем и пресетов

## Контекст

После перевода приложения на русский язык визуальное качество шрифта стало ощущаться хуже. Это ожидаемо: многие гарнитуры, которые выглядят убедительно на латинице, на кириллице теряют ритм, плотность и характер.

Для этого репозитория проблема почти наверняка не сводится только к выбору `fontFamily`. По текущему коду видно, что в пресетах задано много шрифтовых стеков, но в starter-слое не просматривается явная загрузка webfont через `next/font`, `@font-face` или отдельный CSS import. Если реальная загрузка шрифта отсутствует, браузер показывает fallback, и визуальное ощущение темы сразу уходит.

## Что обычно делает кириллический шрифт хорошим

Хорошая кириллическая гарнитура для UI и бренда должна:

- уверенно держать формы `Ж`, `Д`, `Л`, `Й`, `Ы`, `Щ`, `Ц`, `Я`
- не становиться слишком темной и липкой в весах `600`, `700`, `800`
- сохранять читаемость в коротких label, табах, кнопках и form UI
- не требовать агрессивного отрицательного `letter-spacing`
- иметь нормальную экранную подсказку и ровный ритм в размере `14px`-`18px`
- быть достаточно нейтральной для интерфейса, если она используется как основной текстовый шрифт

Для русского интерфейса обычно работает такой подход:

- body copy: `400` или `500`
- UI labels: `500` или `600`
- display headings: осторожнее с `700+`, особенно на узких или геометричных шрифтах
- line-height: чуть свободнее, чем для чисто латинского UI
- letter-spacing: минимальный отрицательный трекинг или вообще без него

## Что важно именно для этого репозитория

### 1. Часть пресетов явно проектировалась с приоритетом латиницы

В landing-пресетах часто используются display-стеки вида:

- `Space Grotesk`
- `Sora`
- `Fraunces`
- `Mulish`
- `Avenir Next Condensed`

Для английского это может выглядеть выразительно. Для русского такие связки часто дают один из эффектов:

- заголовок кажется слишком шумным
- буквы выглядят непривычно плотными
- крупные слова теряют элегантность
- пресет начинает выглядеть как fallback, а не как брендовый выбор

### 2. Есть высокая вероятность, что фактически рендерится fallback

Если шрифт не загружен реально, а только прописан в `fontFamily`, пользователь видит один из запасных системных шрифтов. Тогда проблема ощущается как "русский смотрится плохо", хотя на самом деле сломан не только подбор, но и механизм доставки гарнитуры.

### 3. Нужно отдельно проверить `direction`

В части дефолтных тем в коде встречается `direction: "rtl"`. Для русского языка это неверно. Даже если активный starter сейчас сидит на `landingPageThemes`, это все равно нужно держать в поле зрения, потому что для русскоязычного продукта направление должно быть `ltr`.

## Практический вывод

Если задача в том, чтобы русский бренд выглядел уверенно и коммерчески, нельзя полагаться только на эффектный display-шрифт. Для кириллицы надежная стратегия такая:

- один сильный основной UI-шрифт с хорошей кириллицей
- один акцентный display-шрифт только там, где он действительно нужен
- один моноширинный шрифт для технических и data-heavy блоков

Это дает теме характер, но не ломает читаемость на русском.

## Рекомендуемые open-source шрифты для коммерческого использования

Ниже список практичных кандидатов, которые подходят для коммерческого бренда и имеют смысл для кириллицы.

### 1. IBM Plex Sans

Лучший рациональный выбор для интерфейсов, SaaS, dashboard и B2B-продукта.

Сильные стороны:

- хорошая кириллица
- зрелый технический характер
- не выглядит "слишком дефолтно"
- отлично работает в UI и в полужирных весах
- хорошо сочетается с `IBM Plex Mono`

Когда выбирать:

- product UI
- B2B
- design system
- structured, tech, operational presets

### 2. Golos Text

Один из самых логичных вариантов, если русский язык важен не как вторичная локаль, а как основная среда бренда.

Сильные стороны:

- очень уверенное ощущение на русском
- хороший экранный ритм
- спокойный, современный, не безликий
- лучше чувствует русскоязычную среду, чем многие универсальные гротески

Когда выбирать:

- русский-first продукт
- лендинги и интерфейсы с большим количеством текстов
- бренд с локальной языковой идентичностью

### 3. Manrope

Более мягкий и дружелюбный современный вариант.

Сильные стороны:

- современный внешний вид
- чистая форма
- подходит и для marketing, и для UI
- не такой безличный, как слишком нейтральные системные решения

Когда выбирать:

- clean landing
- friendly product brand
- modern SaaS

### 4. Inter

Самый безопасный и понятный baseline.

Сильные стороны:

- стабилен
- привычен
- удобен для интерфейсов
- хорошо работает в таблицах, формах и плотном layout

Ограничение:

- брендово может быть слишком нейтральным
- если нужен выразительный характер, одного `Inter` мало

Когда выбирать:

- если важнее надежность, чем индивидуальность
- как fallback или технический baseline

### 5. Source Serif 4

Сильный кандидат для editorial, strategy, trust-heavy и content-led тем.

Сильные стороны:

- хорошая кириллица
- интеллектуальный и содержательный характер
- подходит для больших заголовков и длинного чтения

Когда выбирать:

- editorial presets
- premium content surfaces
- trust, thought leadership, strategy pages

### 6. Source Sans 3

Хороший партнер для `Source Serif 4`, если нужна строгая и чистая пара serif + sans.

Когда выбирать:

- editorial system
- контентный продукт
- смысловой и доверительный визуальный тон

### 7. Unbounded

Использовать только как акцентный display-шрифт.

Сильные стороны:

- очень заметный характер
- работает для loud, futuristic, experimental hero-блоков
- поддерживает кириллицу

Ограничение:

- не подходит как основной текстовый шрифт
- быстро утомляет в UI и длинных словах на русском

Когда выбирать:

- только для hero и крупного брендинга
- только в паре с нейтральным body-шрифтом

### 8. IBM Plex Mono или JetBrains Mono

Для кода, метрик, терминальных и data-heavy поверхностей.

Практический вывод:

- `IBM Plex Mono` обычно лучше подходит в общую бренд-систему
- `JetBrains Mono` сильнее ощущается как developer/engineering voice

## Наиболее разумные пары для этого проекта

### Вариант A. Самый рациональный

- body/UI: `IBM Plex Sans`
- display: `IBM Plex Sans`
- mono: `IBM Plex Mono`

Подходит для:

- design system
- starter
- showcase
- русской продуктовой версии без лишнего риска

### Вариант B. Русский-first бренд

- body/UI: `Golos Text`
- display: `Golos Text` или `IBM Plex Sans`
- mono: `IBM Plex Mono`

Подходит для:

- русскоязычного продукта
- локального бренда
- интерфейсов, где язык должен ощущаться естественно, а не как адаптация

### Вариант C. Современный friendly SaaS

- body/UI: `Manrope`
- display: `Manrope`
- mono: `IBM Plex Mono`

Подходит для:

- clean, modern, polished product
- landing + app в одном визуальном тоне

### Вариант D. Editorial / strategy

- body/UI: `Source Sans 3`
- display: `Source Serif 4`
- mono: `IBM Plex Mono`

Подходит для:

- контентных лендингов
- thought leadership
- премиального и содержательного тона

### Вариант E. Экспериментальный landing

- body/UI: `IBM Plex Sans` или `Inter`
- display: `Unbounded`
- mono: `IBM Plex Mono`

Подходит для:

- hero section
- campaign page
- акцентных landing-пресетов

Не подходит как единая система для всего приложения.

## Рекомендация по умолчанию

Если нужен один надежный выбор без лишнего риска, лучшая отправная точка:

- основной шрифт: `IBM Plex Sans`
- моноширинный: `IBM Plex Mono`
- editorial-акцент при необходимости: `Source Serif 4`

Если продукт ощущается русскоязычным по своей природе, а не просто переведенным, альтернативный лучший путь:

- основной шрифт: `Golos Text`
- моноширинный: `IBM Plex Mono`

## Что стоит сделать дальше в коде

1. Проверить, загружаются ли webfonts реально, а не только перечислены ли они в `fontFamily`.
2. Привести русскую версию к `direction: "ltr"` в тех пресетах, где это важно.
3. Снизить агрессивность display-типографики для русского:
   - меньше отрицательный `letter-spacing`
   - осторожнее с `800/900`
   - чуть свободнее `line-height`
4. Отделить базовый UI-шрифт от акцентного display-шрифта.
5. Сравнить минимум три пары на живом экране:
   - `IBM Plex Sans` + `IBM Plex Mono`
   - `Golos Text` + `IBM Plex Mono`
   - `Manrope` + `IBM Plex Mono`

## Итог

Проблема выглядит не как "русский язык сам по себе портит дизайн", а как сочетание трех факторов:

- пресеты местами типографически заточены под латиницу
- часть display-решений слишком агрессивна для кириллицы
- есть высокая вероятность, что сейчас приложение показывает fallback вместо реально подключенной гарнитуры

Для коммерческого open-source решения с хорошим русским видом самый сильный безопасный выбор:

- `IBM Plex Sans`
- `Golos Text`
- `Manrope`
- `Source Serif 4` для editorial-направления
- `IBM Plex Mono` для mono-слоя
